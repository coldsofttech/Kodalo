# UI

The desktop window is hosted by [Cornea Shell](https://github.com/coldsofttech/CorneaShell) (`cornea-shell`). It runs on Windows only; the library, command line and API work on every system.

## Static files, dynamic app

Cornea serves the built files in `src/kodalo/ui/ui/dist`, but the page is a normal single-page app that talks to Python while it runs. `ui/` holds only the interface; everything dynamic lives in `kodalo.api` and `kodalo.core`:

- **Data:** `fetch('/api/v1/...')` calls the `kodalo.api` routes and gets JSON.
- **Native actions:** `POST /api/bridge/<action>` runs a Python function registered in `kodalo/ui/app.py`. `app_info` returns the app name and version for the About page. Cornea also provides file and folder pickers, opening links and platform info.
- **State:** lives in React in the page, and in Python behind the routes.

Cornea hosts the page and the API on one address, behind a start-up token that becomes a session cookie, a host and origin check, and strict response headers. See [security](security.md).

## Layout

```text
src/kodalo/ui/__main__.py   the `kodalo-ui` command: options, output, exit code
src/kodalo/ui/app.py        builds the Cornea shell: serves dist, mounts the API, registers actions
src/kodalo/ui/ui/           React + Vite (JavaScript): src/, index.html, package.json, tests
src/kodalo/ui/ui/dist/      build output, not committed; frozen into the Windows build
```

`app.py` only wires things together. It must not hold business logic, and `kodalo.api` and `kodalo.core` must never import `kodalo.ui`.

## Running it

```bash
uv sync
npm ci --prefix src/kodalo/ui/ui
npm run build --prefix src/kodalo/ui/ui
uv run python -m kodalo.ui                 # window
uv run python -m kodalo.ui --no-window     # prints an address for a browser
uv run python -m kodalo.ui --dev           # Vite with hot reload (needs Node)
```

`--dev` starts `npm run dev` through Cornea and relaxes the content security policy for Vite. Use it only while developing.

## Screens

- **Brands** is the first screen. With no brand yet it shows a welcome page (choose a starter palette, name the brand, or import a file). Otherwise it shows the list of brands, the editor and a live preview. The editor has four tabs: Colors (light and dark values, with a contrast check, and a way to save the colors as a palette), Fonts, Logo and Layout (choose a shared layout from a drop-down; the preview follows it). Edits are a draft: the preview follows every change, and nothing is written until you press Save (Discard throws the draft away, and leaving with unsaved changes asks first). Logo uploads and removals are the exception: the file is stored on the server, so they are saved straight away.
- **Opening a page** always starts it fresh: only the open page is mounted (`App.jsx`), so leaving a page drops its state and coming back reloads it from the server. A page or form with unsaved edits tells the app through `useUnsavedGuard` / `useSavedValues` (`src/libs/unsaved.js`); leaving it then asks *Discard changes* or *Keep editing*. The Brands editor, the Studio copy editor and the Settings forms (GitHub, AI connections, Platforms and the Instagram fields, Appearance, history settings) report their edits.
- **Canvases**, **Palettes** and **Layouts** are sub-menus of Brands in the navigation (`src/pages/brands/`). Each lists the built-in and your own items and lets you add, edit, copy, export, import and delete your own (`/api/v1/canvases`, `/palettes`, `/layouts`); built-in ones are read-only, and one in use cannot be deleted. A layout chooses a canvas, margins, corner radius, text settings and the number of slides. Changing any list tells the brand editor to reload its lists.
- **Repositories** (after Studio) adds, lists and removes the repositories posts are made from. Add takes a folder in `local_folder` mode, otherwise a GitHub address, and checks it (`POST /api/v1/repositories/check`). A folder that was not added before first asks for the owner, repository name, license and default branch (git prefills what it can), plus optional details. Then it reads and keeps the repository (`POST /api/v1/repositories`). Adding a repository, or pressing Edit on a row, opens the repository screen (`GET /api/v1/repositories/{id}`): metadata, languages, top-level files, notable folders, project files (package, version and dependencies), the monorepo flag, frameworks and tooling, then warnings. Top level, Notable folders, Frameworks, Tooling and Project files are collapsible sections that start closed, each with a count; folders and files have Bootstrap icons, and Refresh and Refresh with AI are icon buttons. When the owner uploaded a social preview on GitHub (found with the GitHub CLI, kept in the data folder's `social_previews` folder), an image button next to the home button at the top opens it full screen in a dialog like the slide preview (Esc, Close or a click outside closes it). Refresh reads it again (`POST /api/v1/repositories` with `refresh`), Refresh with AI is described below. The top bar (title, description, Social preview when there is one, Back, Next and, after a gap, Home) stays the same on both screens. Next opens the Analyze screen, which reads the README and the docs it links to (`POST /api/v1/studio/repositories/{id}/readme`) and shows the purpose, how to install the product, its capabilities, features and use cases as collapsible sections (closed at first, the lists as tables with a count); the document each installation method or capability was found in shows as a badge. The documents read or skipped are not listed. A saved result is shown as is, and Refresh reads again. The repository details also show the repository's own icon, or "None found" once the README analysis with AI has looked. `Refresh with AI` calls `.../readme/analysis/plan`, lists the documents and the estimated tokens in a confirmation panel, and only on `Proceed` calls `.../readme/analysis` once, then shows the improved result; see [readme-analysis.md](readme-analysis.md). On the Analyze screen Back returns to the details and Next is disabled; on the details Back is disabled. Home returns to the table. The table lists each repository with Edit and Remove buttons (`DELETE /api/v1/repositories/{id}`).
- **Studio** is where a post starts. Step 1 picks one of the repositories added on the Repositories page (`GET /api/v1/repositories`), with a link to that page. Next loads the repository and its saved or freshly read README analysis and opens the Focus step (Tool / Utility post or Feature post, and for a feature post which feature, use case or capability). Next first asks for the ideas saved for that repository and focus (`GET /api/v1/studio/repositories/{id}/ideas`) and shows them without calling the AI. When none were made yet it calls `.../ideas/plan` and shows a confirmation with the model and the estimated tokens; only on `Proceed` does it call `POST /api/v1/studio/repositories/{id}/ideas` once, with the AI overlay covering the page, and opens the Ideas step with a strategy, three angles with hooks and five post ideas, which are saved in the database. The `Refresh with AI` icon in the top bar of the Ideas step asks again (confirmation first) and replaces the saved ideas. The Ideas step shows one compact card per idea (choose one, optionally another of its angle's hooks, and fold out its beats and visual concept), and Copy puts one idea on the clipboard as text. Next on the Ideas step looks for the copy saved for the chosen idea, hook and brand (`GET .../copy`) and shows it; when none was written it asks first (`POST .../copy/plan`, the same confirmation panel) and only on `Proceed` writes it (`POST .../copy`, with the AI overlay). The platform comes from the selected brand's canvas, and only Instagram is supported so far: another platform shows an error asking for an Instagram brand. The Post step shows the slides (or the single image's text), the caption, the alternative opening and the hashtags as editable fields with Save changes (`PUT .../copy`), and the `Refresh with AI` icon writes it again. Next on the Post step opens the design: it looks for the saved design of the post (`GET .../design`) or, when none was made, asks first (`POST .../design/plan`, the same confirmation panel with the tokens, and a line when the social preview is sent too) and only on `Proceed` makes it (`POST .../design`, with the AI overlay). The design step shows the slides as a grid with a Light and Dark toggle and a full-screen preview like Brands (arrow keys, Esc), and the caption and hashtags below. Every slide, whether a fixed template or the AI's layout, is a page the server builds (`GET .../design/slide`) shown in a frame that can run nothing; the pages are also stored in the data folder when the post is designed. When the brand's canvas is an Instagram one, a Post and an Export icon button sit at the right of the Slides heading (hidden for Custom canvases). Post is only shown once Instagram is connected in Settings > Platforms: it opens a banner saying which account it posts to and as what (a single image or a carousel), that Cloudflared will be installed, and asks once more; confirming checks `GET /api/v1/settings/platforms/instagram/tunnel`, installs Cloudflared with `POST` on the same path behind its own screen when it is missing, then posts with `POST .../design/post` behind an Instagram screen. Export always shows: it asks for a folder with Cornea's folder dialog (`choose_folder`, only in the window) and calls `POST .../design/export`, which writes the slides as pictures and a `caption.txt` into a new subfolder, for posting by hand without connecting Instagram. About says Kodalo will install Cloudflared, a third-party tool required for posting directly to Instagram. A slide is drawn by the app from the saved copy's text, the design plan (template, alignment, picture, icon) and the brand's colors, fonts and sizes, set as CSS variables; the AI never writes text and no AI markup is shown. Pictures are the social preview, the repository's icon (or the logo cut out of the social preview by the box the AI found) and one-color drawings the AI made, which are cleaned and shown as a mask in the brand's color. `Refresh with AI` designs again. Settings > Platforms decides what the designer may use. With Use AI-powered templates/styles on, the AI does not choose from the fixed templates but writes one stylesheet for the whole post and a layout for each slide made of plain boxes with slots (a longer answer, so the confirmation says it costs more). It also decides where the repo name shows (every slide, first and last, first, last or none) and whether the app draws progress dots or a bar. The AI writes no text: the app puts the saved headline and body into the slots under a fixed type scale (headline 96, 76, 60 or 52 px by length at 1080 px wide, body 38 or 34 px), so a slide always shows the copy and nothing else. The app also draws, identically on every slide, the brand's logo (or the repo name as a wordmark when the brand has none), the footer, the slide number and the progress marks. Pictures and the logo are embedded in the slide page as data, because the frame cannot send the window's login to the API. Each slide is shown in a sandboxed frame with no permissions (`sandbox=""`) pointing at `GET .../design/slide`, scaled to its card, and follows the Light and Dark toggle. The settings are enforced in code, not only asked for in the prompt: a layout that draws a diagram out of empty boxes is refused unless Build custom images is on, only allowed pictures and real Bootstrap icons survive, a stylesheet with `!important`, `url()` or `@` rules is refused, and when the AI leaves out every allowed picture the app adds one to the first slide. A refused slide keeps its fixed-template design, and warnings above the slides say what happened, including when icons are on but none was used. See [post-ideas.md](post-ideas.md).
- **Settings** has GitHub connectivity: choose the GitHub CLI (default), a local folder or web fetch, set how many project files are read from GitHub and how many documents (and how much of each) are read for the README analysis, save it, and test the saved choice (`/api/v1/settings/github`).
- **Settings > AI > Models per job** is an accordion under the AI connections. It lists the six jobs done by AI (palette suggestion, repository metadata, repository features, Studio ideas, copywriter and designer) and lets each use any model of the active connection, or the connection's default model (`/api/v1/settings/ai/task-models`). A saved choice whose model is gone falls back to the default. The accordion reports unsaved changes.
- **Settings > AI History** lists every call made to an AI model (palette suggestions, Studio steps and connection tests) with its date and time, title, purpose, connection, model, status and tokens. Pick a period (last day, week, month, year, all time or a custom range) to filter it, the token table per connection and model, and the chart of tokens per day. Opening an entry shows what was sent and what came back when the text was kept. Two settings control the history: keep the text of prompts and answers (off by default) and remove entries after a number of days (90 by default, 0 keeps them); `Purge history` removes everything after a confirmation (`/api/v1/settings/ai/history`, `/api/v1/settings/ai/usage`).
- **Settings > AI Connections** has a Provider dropdown (Claude API, Claude Code, ChatGPT API, Gemini API); choosing one shows that provider's options. Every provider starts switched off. Turn it on, enter the API key (a password field that is cleared after saving; only the last characters are shown afterwards), set another address, test it and make it the default. Each card lists the models with their default, maximum tokens, temperature and timeout, and can refresh them from the provider or add one by hand (the model name box suggests the refreshed names, and choosing a saved one loads its settings; new models start with Kodalo's standard settings) (`/api/v1/settings/ai/connections`).
- **Settings > Platforms** has a Platform dropdown (Instagram) with the number of hashtags a post gets (0 to 30, the default ones included) the default hashtags every post carries, and four switches for what the designer may use: Use social preview, Use repo icon, Use icons, Build custom images as needed and Use AI-powered templates/styles (all off at first). They are saved with `/api/v1/settings/platforms/{platform}` the hashtag settings are used when the AI writes a post's hashtags (the default ones come first and the AI fills the rest); the designer will read the switches.
  - With Instagram chosen, an Instagram connection section above the hashtag settings: paste the Instagram account ID and an access token (password field, cleared after use) to connect, then see the account, check the token again, replace it or disconnect. It uses `/api/v1/settings/platforms/instagram/connection`. A short line says Kodalo will install Cloudflared, a third-party tool required for posting directly to Instagram.
- **Settings > Appearance** chooses the theme: System (default, follows Windows), Light or Dark. It is saved with `/api/v1/settings/theme`, read once at launch by `src/libs/theme.js` and applied to the page (`data-theme`) and to the Fluent components (`src/libs/fluent.js`). The command line has no theme.
- **About** explains the product and has a button that runs the `doctor` checks (`GET /api/v1/doctor`) and shows the result.

The Repositories screen has a `Refresh with AI` button. It calls `POST /api/v1/studio/repositories/{id}/analysis/plan`, shows the estimated tokens in a confirmation panel, and only on `Proceed` calls `POST .../analysis` once, then reads the repository again. One request covers parsers, frameworks and tools: the start of unknown project files, plus package and file names, with one combined confirmation. The repository view also shows the documentation files found and the files that were not read (with the reason). It lists the recognised frameworks and the tooling (build, test, lint and format, CI, containers, package tools) with their evidence.

## The preview

`preview.jsx` draws sample slides (cover, content, code, quote and call to action) from the draft brand. It sets the brand's colors, fonts and sizes as CSS custom properties on one element with `style.setProperty`, which Cornea's content security policy allows (an inline `style` attribute would not be). Sizes are written in canvas pixels and scaled with the slide's container width, so every slide keeps the proportions of the chosen canvas. `src/libs/brand.js` holds the mapping from brand data to those variables; the slide designer that renders the final images must read the same fields the same way.

## Writing the frontend

- Plain JavaScript with JSX. Call Python only through `src/libs/api.js`.
- Cornea's policy forbids inline scripts and styles, so put styles in CSS files.
- **Fluent UI Web Components** (`@fluentui/web-components`, MIT) provide the buttons, text and number fields and switches. They are registered once in `src/libs/fluent.js` (which follows the system light or dark theme), and `src/components/controls.jsx` wraps them for React: a custom element keeps its value as a property and reports changes with DOM events. They add their styles through adopted style sheets, which the content security policy allows. Tabs, the navigation, selects and the colour picker are native elements styled with CSS.
- **Fonts** are bundled from the `@fontsource` packages (SIL Open Font License, latin subset, weights 400, 600 and 700), imported in `src/styles/fonts.css`. They are dev dependencies because Vite copies the files into `dist`. The list of font names is in `kodalo.core.brands.brand.fonts`.
- `npm run lint`, `npm test` (Vitest, Testing Library and an accessibility check) and `npm run build` run in CI. Tests do not register the Fluent elements; `src/testing.js` has a fake API and helpers to "type" into them.

## Packaging

The window is not part of the Python package: `uv build` publishes only the core library and the command line. Users get the window from the Windows installer, which freezes `ui/dist` into the build (`installer/pyinstaller/ui.spec`) and needs no Node. The `kodalo-ui` command exists in that build; from the source tree you start it with `python -m kodalo.ui`.

The window and taskbar icon is `src/kodalo/ui/ui/public/icon.png` (copied into `dist` by the build), and the app id, title and version are constants at the top of `kodalo/ui/app.py`. The Windows setup and the standalone executables are described in [packaging](packaging.md).

## Tests

The Python tests in `tests/ui/` replace Cornea's `Shell`, so no window opens. In `tests/ui/integration/`, a Windows-only test starts the real server without a window and needs a built `dist`, and another starts the built `kodalo-ui.exe` (see [packaging](packaging.md)).

While the AI works (Palettes > Suggest with AI after `Proceed`, and Repositories > Refresh with AI after `Proceed`), a see-through screen with an animated robot covers the window and blocks clicks until the answer arrives; with reduced motion the animation stops. The animation is CSS and Bootstrap icons only, because the content security policy forbids inline styles.

A plain Refresh on the repository and Analyze screens shows the same overlay with a turning refresh icon while GitHub and the documents are read.
